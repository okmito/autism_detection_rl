Adaptive Autism Screening — Question Selection

A rule-based information-gain policy picks which Q-CHAT-10 questions to ask · budget-constrained · research prototype
⚠ Screening research demo — NOT a diagnosis

Run a screening episode

No reinforcement-learning policy is served here. The RL arms (DQN, PPO) are benchmarked offline in scripts/step5_policy_benchmark.py; this demo runs the information-gain and random baselines so the selection logic is inspectable.
Why did Random ask fewer questions? The random baseline draws uniformly from the legal actions, which include “stop”, so it can end the episode early — including before asking anything at all (~9% of episodes ask zero questions, and only ~45% reach the full budget of 6). This is a property of the baseline as specified, not an adaptive decision, so its question count is not comparable with the greedy policy's.
How it works
  • The policy chooses which question to ask next (max 6 of 10).
  • Greedy is deterministic: it scores every unasked question by expected information gain about the label, given the answers so far, and takes the best — the same answers give the same sequence by design.
  • Random draws a fresh random action each step, including “stop”, so it can finish early — a baseline for comparison, not an adaptive policy.
  • After each answer the model updates the risk estimate.
  • “Stop & predict” ends early and gives the recommendation.
  • Auto mode replays a full episode from the held-out test set.
Why does it often ask A1, A2, A3… in order? On this dataset the labels are a deterministic sum-threshold over the questions themselves, so after a few answers every training record still consistent with your answers carries the same label. The support is then label-pure, expected information gain is exactly 0 for every remaining question, and argmax has nothing to choose between — the policy falls back to the lowest-numbered unasked item. This is measured, not a bug in the demo, and it is shown per step in the Selection panel below.
