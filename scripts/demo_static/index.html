Why did Random ask fewer questions? In Auto episode mode the random baseline draws uniformly from the legal actions, which include “stop”, so it can end an episode early — only some episodes reach the full budget. Its question count is then not comparable with the greedy policy's. In Interactive mode the random arm always asks the full budget, because stopping there is a manual action.
No reinforcement-learning policy is served here. This demo runs the information-gain and random baselines so the selection logic is inspectable; learned policies are benchmarked offline.

Why does it often ask A1, A2, A3… in order? On this dataset the labels are a deterministic sum-threshold over the questions themselves, so after a few answers every training record still consistent with the answers given carries the same label. The support is then label-pure, expected information gain is exactly zero for every remaining question, and argmax has nothing to choose between — the policy falls back to the lowest-numbered unanswered item. This is measured per step in “Why this question?” via the backend's criterion_vacuous flag. It is a property of the data, not a defect in this interface.

This is an AI-assisted research screening tool, not a diagnostic instrument. Results require interpretation by qualified healthcare professionals. This research prototype is intended for screening research and does not provide a medical diagnosis. Default acquisition policy is Greedy Information Gain (configs/config.yaml: policy.type=greedy). Experimental components (hybrid IRT+EVOI, adaptive stopping) are preserved for reproducibility and are not part of the default path. Bayesian predictive SD is an experimental model diagnostic (ECE 0.20–0.24 on held-out data — probabilities are not clinically calibrated) and never gates stopping.
